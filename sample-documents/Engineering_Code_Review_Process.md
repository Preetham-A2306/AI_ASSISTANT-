# Branch Naming
Engineering branches use the format `type/short-description`, for example `feature/profile-search` or `fix/login-timeout`.

# Pull Request Submission
Push your branch to the company Git repository and open a pull request against the `main` branch. Include a clear summary, testing notes, and screenshots when the change affects the UI.

# Reviewer Requirements
Every production-bound pull request requires at least one reviewer from the owning engineering team. Changes affecting security or data access require an additional reviewer familiar with the affected area.

# Approval and Merge
Address reviewer comments before merging. A pull request may be merged after required approvals and successful CI checks. The author should use squash merge unless the team manager documents another strategy.
